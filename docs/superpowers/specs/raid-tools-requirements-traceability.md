# Raid Tools (Tank Cast / Raid Groups) — Requirements Traceability

> Living document. Update it whenever a requirement is added, changed, or its
> implementation moves. Cross-check the touched rows before declaring any
> Tank Cast / Raid Groups task done — not just the row for the current ask.
> See memory `raid-tools-requirements-traceability-process` for why this
> file exists and how to apply it.

Format per row: **ID** — requirement statement — **Status** — **Verification**.
Status is one of: `Shipped`, `Shipped (bug found+fixed)`, `Designed (awaiting approval)`, `Deferred`.
Verification points at what proves the row true right now: a test name, a
`file:line`, or a live-harness observation (with the date it was checked).

Modules: `AutoInvitePlus/modules/TankCast.lua` (`TK`), `AutoInvitePlus/ui/TankCastWindow.lua`,
`AutoInvitePlus/ui/TankCastConfig.lua`; `AutoInvitePlus/modules/RaidGroups.lua` (`RG`),
`AutoInvitePlus/ui/RaidGroupsWindow.lua`. Headless specs: `tools/tests/tankcast_spec.lua`,
`tools/tests/raidgroups_spec.lua`.

## Design note for RG-020 (full-cell state representation) — design complete, awaiting user approval

**User correction (2026-09-27, mid-round):** the original plan (a small ready-check icon reusing the presence-dot's corner) was rejected. Player state — dead/offline/AFK/DND *and* ready-check (ready/not-ready/waiting) — must be a **full-cell visual treatment**, not a small dot. A dedicated design pass was delegated to a subagent (general-purpose, instructed to act as a senior game UI/UX designer); it read `ui/RaidGroupsWindow.lua` directly for ground truth on the existing layout/constraints and published a mockup.

**Mockup:** https://claude.ai/artifact/5xH4DLyH9Dg9zNz5NRWJ8w — shows all 8 states at 6x scale (780×132px per cell = the real 130×22px), each against a deliberately adversarial class colour (DK red, Priest white, Rogue yellow, Druid orange) to stress-test that the treatment survives worst-case hue clashes, plus a Dead+Not-Ready combo cell and a realistic 40-person/8-group grid at 3x scale for at-a-glance readability.

**Recommendation: three independent, redundant signal channels (not one)** — chosen specifically because a single hue-only wash failed the stress test (see Alternatives below):
1. **Fill wash** — whole-cell darkening, brightness-only, never relies on hue (doesn't fight class colour).
2. **Ring** — 1px inset border, state-coded hue, kept clear of the existing gold target-border's hue.
3. **Text label** ("DEAD"/"OFFLINE"/"AFK"/"DND") — the colourblind-accessibility backstop.
4. **Ready-check icon** — Blizzard's own real `Interface\RaidFrame\ReadyCheck-Ready`/`-NotReady`/`-Waiting` textures (shape-coded), shown independently on top of whatever else is displayed — not part of the persistent-state priority stack, since it's short-lived (≤35s) and the most actionable thing mid-check.

**Priority order — persistent-state channel (mutually exclusive):** `Offline > Dead > DND > AFK > Normal`. **This flips the order already shipped in the current (soon-to-be-replaced) `cell.stateDot` code** (`dead > offline > dnd > afk`, `refreshValues`) — flagged by the design agent as a deliberate proposed change for the implementer/user to confirm, not an oversight. Reasoning: Offline is total information loss (matches Grid/Blizzard convention).

**Ready-check channel:** independent of the above, always shows on top when active for that unit, regardless of persistent state (demonstrated by the Dead+Not-Ready mockup cell). **Target ring:** always outermost/topmost, one frame level above the state ring, so a targeted+dead player shows both simultaneously.

This is a bug in code already shipped, not yet fixed — folded into RG-020's implementation, not treated as a separate row, since fixing it makes no sense in isolation from the full-cell rework it's part of.

Everything above is a texture colour/alpha or backdrop-colour change, or Show/Hide on a plain (non-secure) child object — safe to update live in `refreshValues`, exactly like `cell.targetBorder` already does. All *new* objects are created once in `acquireCell`, out of combat only, per the existing pattern.

**Alternatives considered (and why rejected):** (1) hue-only wash on the class-colour background directly — failed the adversarial-colour stress test (e.g. red Dead wash nearly invisible on a Death Knight's red background); (2) ring+label only, no wash — zero risk to the icon layer, but the ring alone is the weakest signal in the mockup, so at-a-glance triage across a full raid is noticeably weaker; kept as a conservative fallback option.
